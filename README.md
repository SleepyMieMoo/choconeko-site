# ChocoNeko team website

The website for **ChocoNeko**, a chocolate-and-cat themed Roblox hub game that is currently in development. It introduces the game, explains how it is made and lists the team.

Live site: https://sleepymiemoo.github.io/choconeko-site/

## How it works

This is a plain static site: HTML, CSS and a little vanilla JavaScript. There is no build step and no dependencies. It is hosted with GitHub Pages straight from the `main` branch.

| Path | What it is |
| --- | --- |
| `index.html` | Home page: hero, about, team and links |
| `members/sleepymie.html` | SleepyMie's member page |
| `js/members.js` | The team list shown on the home page |
| `js/main.js` | Theme picker, mobile menu, footer year and team cards |
| `css/themes.css` | All theme colours (generated, do not edit by hand) |
| `css/style.css` | Layout and components; uses only the theme variables |
| `tools/sync-themes.py` | Regenerates `css/themes.css` from the game's themes |
| `img/` | Logo and social preview image |
| `404.html` | Page shown for missing URLs |

To preview it, open `index.html` in a browser or serve the folder with any static file server.

## Themes

The site offers every UI theme from the game, with the same names and colours. Visitors pick one with the **Theme** menu in the header (inside **Menu** on phones). The first option, **System (match device)**, is the default: a device in dark mode gets Dark Choco (the game's default theme) and a device in light mode gets Vanilla. It follows the device setting live. The choice is saved in the browser (`localStorage`), and a tiny script in each page's `<head>` applies it before the page is drawn, so there is no flash of the wrong theme.

How the colours fit together:

- `css/themes.css` is the single source of theme colours on the site. It is generated by `tools/sync-themes.py` from the game's theme definitions. It holds one block of CSS variables per theme (`<html data-theme="...">`), the System mapping and the list of themes shown in the picker.
- Base colours are copied unchanged from the game (`panelBg` becomes `--panel`, `elevatedBg` becomes `--elevated`, `accordionHeaderBg` becomes `--deep`, `textColor` becomes `--text` and so on; the full mapping is at the top of `css/themes.css`).
- A few site-only colours are derived from them (muted text, link colour, focus outline, control borders, outlines). The script nudges these only as far as needed to pass WCAG AA: 4.5:1 for text, 3:1 for large text, controls and the focus outline.
- `css/style.css` never hard-codes a colour. It only uses these variables.

## Adding or changing a theme

**Rule: every theme that is added to the game, renamed or recoloured must also be added to or updated on this website.** The site should always offer exactly the game's themes.

1. Get a local copy of the game's current theme definitions file (from the game's main branch).
2. Run the sync script with the path to that file:

   ```sh
   python3 tools/sync-themes.py /path/to/the-game-theme-file --check
   ```

   It rewrites `css/themes.css`, updates the System `theme-color` tags in the HTML pages and prints a contrast report for every theme. It needs only Python 3, with no extra packages.
3. Check the contrast report. It must end with `contrast: all pairs pass WCAG AA` (with `--check` the script exits with an error otherwise). If a pair fails, adjust how the derived site colours are calculated in `site_colors()` in the script. Never change the game's own colour values here.
4. Preview the site, pick the new or changed theme in the Theme menu and look at the home page, a member page and the 404 page at desktop and phone widths.
5. Commit `css/themes.css` together with any HTML files the script updated, with a message such as `Sync themes: add Caramel`, then push to `main`.

Notes:

- Never edit `css/themes.css` by hand; the next sync overwrites it.
- Theme names, order and colours come from the game. The picker order is the game's theme order, and the default theme is the game's default.
- If a theme is removed from the game, the sync removes it too. Visitors who had picked it go back to System.
- The theme used for System on light devices is `LIGHT_SYSTEM_THEME` at the top of the script.
- The script's docstring explains the input format it understands. If the game's theme file changes shape and the script stops with an error, update the parser there.

## Adding a team member

1. Open `js/members.js` and add an object to the list, for example:

   ```js
   {
     id: "newmember",
     name: "NewMember",
     role: "Role",
     blurb: "One short line about what they do.",
     page: "members/newmember.html"
   }
   ```

   Use the name exactly as the person wants to be credited. `page` and `website` are optional.

2. (Optional) For a member page, copy `members/sleepymie.html` to `members/<id>.html` and update the name, role, avatar letter, title, description, social preview tags and links.

3. Commit and push to `main`. GitHub Pages updates the live site automatically.
